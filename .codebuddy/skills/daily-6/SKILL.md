# 每日六条

> 本文件只管「抓什么、选什么、怎么排版」。怎么写看 `WRITING.md`（唯一规则表），阶段顺序与产物看 `SHORTNEWS-V1.md`，出图看 `工具/PROMPT.md`，一条龙出稿看 `出稿.sh`。

一天一套，六条选题各配三张卡与 X、Threads 各一条帖。只做当天有什么，不做单条深挖，那个是 `topic-1`。

## 0 · 开工前

- 先读 `HANDOFF.md` 自动段，翻 `选题台账.md` 去重。
- 依赖 `node`、`python3`、`playwright-cli`。
- 写 JSON 前读完 `工具/PROMPT.md` 的页型与 design token。
- 页脚账号在 `工具/brand.txt`，环境变量 `BRAND` 优先。
- 日期用系统当天，`YYYY-MM-DD`。

## 1 · 抓取（只看近 24 小时）

按四层过一遍，一层都不能省：

| 层 | 源 | 拿什么 |
|---|---|---|
| 官方 / 媒体 | theaivalley.com、every.to、blog.google、news.smol.ai | 模型、公司、融资、官方口径 |
| X 侧 | `follow-builders/feed-x.json`、doomers.ai、postcutoff.com、trends24.in | 官方账号原帖与互动数、当下在传什么 |
| 讨论侧 | Hacker News、Reddit r/LocalLLaMA、news.smol.ai 的 X 摘要 | 真正在吵什么、反方意见 |
| 中文侧 | 中国日报科技、量子位、机器之心 | 国内公司、本土视角 |

### X 抓取的边界

- `x.com` 的搜索页与时间线需要登录态，直接抓只会拿到空壳。
- 可行路径是公开 feed 镜像、趋势页，或 `web_search` 搜 `site:x.com <关键词>`。
- 趋势页打不开时退化为站内搜索与 HN / Reddit 热帖，不硬编造 trend。
- **X 只当「什么在传、谁在吵」，不当事实源**。引用必须落到原帖链接，拿不到原帖就不写某某发推说。
- X 上的热议只作选题线索，成稿前回到官方原文核数字。

抓完先问今天真正发生的事有几件，少于六件就少发，不许凑。

## 1.5 · X 侧整理（每天落成文字）

产出 `<日期>/X热议.md`，固定三段：

1. **在榜**　trends24 全球榜的 AI / 科技条目，最高位次与相对时间照抄。没有就如实写没有。
2. **在传**　按退化顺序取公开 feed 或月度发布榜，列原帖链接与互动数，标账号与时间。
3. **在吵**　三条争议，各写一句 A 方 / B 方，别写成综述。

每条标可信度：A 可引用（口径明确的量化数据、官方帖原文），B 需核实（仅在榜、二手报道、单一个案），C 只作灵感（AI 自动生成的周报，不进正文）。

退化顺序是公开 feed → doomers → trends24 → `site:x.com` 搜索 → HN / Reddit。全拿不到就写今日 X 侧无可靠线索。

**在榜不等于发布，在传不等于事实**。只有趋势、找不到官方帖的，只能进线索池。

## 2 · 选稿（六条的门槛）

每条至少满足一条，否则换掉：

1. 有一个能查证的绝对数字（金额、倍数、份额、时长、人数）
2. 有一个反转（标题说的和数字说的不一样）
3. 有一个明确的时间点（哪天开、哪天停、哪天到期）

三条硬约束：六条题材不撞（模型 / 产品 / 安全 / 资本 / 硬件 / 政策尽量各占一格）；优先能一句话说清为什么值得转的；中文侧、X 热议各至少留一条线索。

## 3 · 事实底稿（先写，再出图）

每条先落一段底稿，字段固定：

```
标题 / 来源 URL / 发布时间 / 关键数字（含单位与口径）/ 官方引语（原话）/ 未确认项 / 我的判断
```

- 数字逐字对回原文，含单位、百分比、货币、传闻标注。
- 官方没说的一律写进未确认项，不许推演成事实。
- 旧数字标年份。
- X 线索要写清原帖账号、链接、时间，再写官方原文链接。

## 4 · 版式分配（硬约束，先排表再写 JSON）

**六套首图必须是六种不同版式**，这是死线。首图池 13 选 6：

`photo-cover` · `photo-split` · `photo-annot` · `ledger` · `bigfact` · `matrix` · `overlap` · `cover-min` · `cover-split` · `cover` · `quote` · `statement` · `mosaic`

两条禁用组合：`cover` 与 `cover-split` 不同时当首图；`cover-min` 与 `statement` 不同时当首图。骨架太像，同批摆一起会被认成同一套。

**配图纪律**：先跑 `./工具/grab.sh <slug> <一手源 URL>`。og:image、品牌 logo、作者头像、分享卡、AI 生成示意插画都不算配图；真实截图一律走 `shot` 页型并写 caption 与 credit。0 张才是真没有，那时在 set 里写 `noImageReason`，写明查过哪一页、那页上是什么图。抓到的图必须接进 set，`review.py` 会查「img/ 里有图但 set 没用上」。

规则：

1. 六套首图页型两两不同，一个型只用一次。
2. 每套 3 页，套内页型不重复。
3. 全批 18 页做到 18 种页型各一次，`check-layouts.mjs --strict`。
4. 光换标题不算换版式，六张首图要在骨架上不同。
5. 自检把六张首图并排看，要能一眼分出横带 / 竖带 / 幽灵数字 / 点阵 / 三行对照 / 裸数字。
6. 排完写表，表不填不许动 JSON。

## 5 · 出卡

1. 按第 4 节的分配表写 `工具/sets/<slug>.json`。
2. 跑 `node 工具/check-layouts.mjs <六个 slug> --strict`，不通过不许渲染。
3. 渲染、归档、公开页、预览图、台账、闸门、交接全交给 `./出稿.sh <日期> <六个 slug>`，不要手工 cp 中间图。
4. 当天目录最终只留 `文案.md`、`配图/`、`预览图.png`、`X热议.md`，配图命名 `NN-slug-MM.png`。

出图后逐张看：有没有一大块空白、标题里的数字正文是否又抄了一遍、结论条是否只有一句、页码是否连号、六张首图能否一眼分清。

## 6 · 写稿与交付

**只看 `WRITING.md`**（写什么、怎么写、交出什么）与 `SHORTNEWS-V1.md`（阶段顺序、产物契约）。本文件不重复规则，两处说法不一致以 `WRITING.md` 为准。

一句话记住当前契约：繁体中文；每条 X 一条 + Threads 一条，都不拆串、不写评论区；完整来源链接单独占最后一行，不写括号式出处，也不写「原文：」前缀；来源与日期只进事实表和备注。闸门是 `python3 工具/review.py <日期> --check`，不过 `出稿.sh` 会 `exit 1`。

## 7 · 纪律

- 不许编体验。没上手就写官方说法，不写「我用了两天」。
- 不许把传闻写成定论，传闻必须带传闻 / 未确认。
- 不许为凑数加水页，信息点只有三条就只做三张。
- 每套 3 张，上限 5 张；超了拆两组，或把最弱的信息点降级进结论条。
- 六套首图重复直接不算完成，宁可换页型重排。
