# 每日六条

> 2026-10-29 更新：目录与阶段以 `SHORTNEWS-V1.md` 为准（`工具/`、`<日期>/配图/`、`<日期>/文案.md`），平台只剩 X 与 Threads。
> 本文件管「抓什么、选什么」。怎么写见 `WRITING.md`（唯一规则表），出图见 `工具/PROMPT.md`。

一天一套：6 条选题 ×（3 张卡 + 三平台文案）。只做"当天有什么"，不做单条深挖——单条深挖是 `topic-1`。

## 0 · 开工前

- 工作目录：本工作区根（含 `工具/`、`<日期>/配图/`、`<日期>/`）
- 依赖：`node`、`python3`、`playwright-cli`（`npm i -g @playwright/cli`）
- 必读：`工具/PROMPT.md`（页型、design token、文案规则、发布前 10 条检查），写 JSON 前读完
- 页脚账号：`工具/brand.txt`，改账号只改这一个文件
- 当天日期：用系统当前日期，如 `2026-10-28`

## 1 · 抓取（只看近 24 小时）

按四层过一遍，一层都不能省：

| 层 | 源 | 拿什么 |
|---|---|---|
| 官方 / 媒体 | theaivalley.com、every.to、blog.google、news.smol.ai | 模型、公司、融资、官方口径 |
| **X 侧** | doomers.ai、postcutoff.com（X 发帖存档）、trends24.in（趋势榜） | 官方账号原帖与传播量、当下在传什么 |
| 讨论侧 | Hacker News、Reddit r/LocalLLaMA、news.smol.ai 的 X 摘要 | 真正在吵什么、反方意见 |
| 中文侧 | 中国日报科技、量子位、机器之心 | 国内公司、监管、本土视角 |

### X 抓取的边界（实测过，别假装能抓）

- `x.com` 的搜索页与时间线**需要登录态**，定时任务里直接抓只会拿到空壳
- 可行路径：`web_search` 搜 `site:x.com <关键词>`，命中通常是 X 原帖的转述镜像（doomers.ai 记录 AI 公司在 X 的发布与传播量；postcutoff.com 存原帖原文＋日期）；趋势看 `trends24.in` 这类公开趋势页
- 趋势页打不开时，退化为「站内搜索 + HN / Reddit 热帖」，不硬编造 trend
- 想让任务直接读 X 时间线，需要在 IDE 内置浏览器里保持登录态（agent-browser），**默认不开**；要用就明说
- **X 只当"什么在传、谁在吵"，不当事实源**：引用必须落到原帖链接（或镜像给出的原帖），拿不到原帖就不写"某某发推说"
- X 上的热议只作**选题线索**，成稿前必须回到官方原文核实数字

抓完在脑子里过一遍：今天真正发生的事有几件？少于 6 件就减少张数，**不许凑**。

## 1.5 · X 侧整理（每天必须落成文字，不许只写"看过"）

抓完就写，产出 `<日期>/X热议.md`，固定三段：

1. **在榜**——`trends24.in` 全球榜里的 AI / 科技条目：最高位次 + 出现时间（该站只有相对时间，照抄）
2. **在传**——`doomers.ai/launches/<年-月>`：当月 X 上 AI 发布浏览量榜，**按粉丝倍数排序，不按浏览量**，标出账号粉丝数
3. **在吵**——三条争议，各写一句 A 方 / B 方，别写成综述

每条标可信度：

- **A 可引用**：口径明确的量化数据（doomers 浏览量、官方帖原文）
- **B 需核实**：仅"在榜"、二手报道、单一个案
- **C 只作灵感**：AI 自动生成的周报（crew.you 这类），**不进正文**

退化顺序：doomers → trends24 → `web_search` 搜 `site:x.com 关键词` → HN / Reddit。全都拿不到就写「今日 X 侧无可靠线索」，不许拿旧闻充数。

**在榜 ≠ 发布，在传 ≠ 事实**：`GPT-6.1 Terra` 这种只看得到趋势、找不到官方帖的，只能进线索池，不许成稿。

## 2 · 选稿（六条的门槛）

每条必须满足至少一条，否则换掉：

1. 有一个能查证的**绝对数字**（金额、倍数、份额、时长、人数）
2. 有一个**反转**（标题说的和数字说的不一样）
3. 有一个**明确的时间点**（哪天开、哪天停、哪天到期）

另外三条硬约束：

- 六条之间**题材不撞**：模型 / 产品 / 安全 / 资本 / 硬件 / 政策，尽量各占一格
- 优先能用一句话说清"为什么值得转"的
- 中文侧、X 热议各至少留 1 条线索，否则整批视角单一

## 3 · 事实底稿（先写，再出图）

每条先落一段底稿，字段固定：

```
标题 / 来源 URL / 发布时间 / 关键数字（含单位与口径）/ 官方引语（原话）/ 未确认项 / 我的判断
```

- 数字必须能逐字对回原文，**含单位、百分比、货币、传闻标注**
- 官方没说的，一律写进「未确认项」，不许推演成事实
- 旧数字要标年份（例：上线 6 天 200 万下载，是 2025 年的数）
- 来自 X 的线索，底稿里必须写清「原帖 @账号 + 链接 + 时间」，再写官方原文链接

## 4 · 版式分配（硬约束，先排表再写 JSON）

**六套首图必须是六种不同版式，绝不重复。** 这是死线，不是建议。

首图池 13 选 6（都能当封面，骨架差异足够大）：

`photo-cover` · `photo-split` · `photo-annot` · `ledger` · `bigfact` · `matrix` · `overlap` · `cover-min` · `cover-split` · `cover` · `quote` · `statement` · `mosaic`

**新闻原文有配图时，首图优先用 `photo-cover`**（上图下文、图满出血）；要指着图讲细节用 `photo-annot`。图片下载到 `工具/img/<slug>-0N.jpg`，JSON 写相对路径；找不到图就退回纯文字页型，别硬塞。

**两条禁用组合**——骨架太像，同批摆在一起会被认成同一套：

- `cover` 与 `cover-split` 不同时当首图（都是「标题在上 + 满血色块」）
- `cover-min` 与 `statement` 不同时当首图（都是大字 + 大留白）

规则：

1. 6 套首图页型**两两不同**，一个型只用一次
2. 每套 3 页，**套内页型不重复**
3. 全批 18 页里同一页型**最多 2 次**；能做到 18 页 18 种就做到（`--strict`）
4. 光换标题不算换版式：6 张首图必须在**骨架**上不同（有没有色块、大数字在左在右、标题居上居下、有没有留白）
5. 自检办法：把 6 张首图缩略图并排看，要能一眼分出「横带 / 竖带 / 幽灵数字 / 点阵 / 三行对照 / 裸数字」这几类骨架
6. 排完写表，表不填不许动 JSON

默认骨架（18 页 18 种，实测可用；可局部互换，但首图 6 种与"全批不重复"不变）：

| 条 | 首图 | P2 | P3 | 首图骨架长什么样 |
|---|---|---|---|---|
| 1 | `ledger` | `kpi` | `table` | 三行大字数字对照 + 一条紫色分隔线 |
| 2 | `bigfact` | `stack` | `brick` | 250px 单个巨型数字，无大色块 |
| 3 | `cover-min` | `quote` | `mosaic` | 细线 + 左下裸数字 + 要点列表 |
| 4 | `cover-split` | `steps` | `statement` | 标题在上，满血紫带托住数字与三条 |
| 5 | `overlap` | `timeline` | `columns` | 幽灵数字压在标题后面 + 底部结论条 |
| 6 | `matrix` | `versus` | `list` | 两组 20×5 点阵，每格 1% |

## 5 · 出卡

1. 填信息规划表（页 / 页型 / 认领的信息点 / 唯一数字 / 不重复于），见 `工具/PROMPT.md` 第 1.1 节
2. 按第 4 节的分配表写 `工具/sets/<slug>.json`
3. **跑版式查重，不通过不许渲染**：

```bash
node 工具/check-layouts.mjs <slug1> <slug2> <slug3> <slug4> <slug5> <slug6>
# --strict：全批每种页型只许出现 1 次（18 页 18 种）
```

4. 渲染并截图：

```bash
cd 工具 && ./make.sh <slug> && cd ..
for i in 1 2 3; do cp "工具/out/<slug>/slide-0$i.png" "<日期>/配图/NN-slug-0$i.png"; done
```

5. 命名：`<新闻名>-01.png`，英文驼峰或短横，例 `Anthropic-IPO-01.png`、`MAI-DxO-02.png`、`Lingguang-03.png`

**出图后必须逐张看**，检查：有没有一大块空白、标题里的数字正文是否又抄了一遍、结论条是否只有一句、页码是否连号、**六张首图摆在一起是不是一眼能分清**。

## 6 · 写文案

每条按 `<日期>/文案.md` 的结构写：**X 一条帖子 · Threads 一条帖子**，都不拆串、不补评论，外加：

- 每条前面放「事实底稿」和「口径提醒」
- **每条文案的最后一行必须是原文链接**：`原文：<完整 URL>`，完整链接，不用短链、不省略协议
- 文末给「发布建议」（几点发、风险控制、有人追问实测怎么答）

语气三条自检（照 `工具/PROMPT.md` 与历史文案）：

1. **具体的，不抽象的**——「凌晨三点翻完招股书」好过「认真研究了」
2. **带一点损耗**——承认算错、酸、懒得看、被落下；完美人设没人关注
3. **一条只放一句人味**——超过两句就矫情，中间必须是硬信息

Threads 只发一条，不拆串、不排 1/2/3，只用 1 个话题标签放正文末尾。

**来源链接纪律**：

- 每条稿子挂**一个**主来源链接（官方原文 > 一手实测 > 主流媒体），写成 `原文：https://...`
- 抄了多家时，其余链接写进事实底稿，不堆进推文
- 两个平台都是单条：X 链接放正文最后一行，Threads 链接放首评；都不拆串，不写 1/2/3
- 链接失效比没有链接更伤可信度，发前点一遍

## 7 · 交付

- 文案：`<日期>/文案.md`
- 配图：`<日期>/配图/NN-slug-01/02/03.png`（18 张）
- 汇总页：更新根目录 `index.html` 的选题卡片列表（标题、来源、页型、一句话理由、三张缩略图）
- 最后回一条清单：6 条标题 + 每条首图页型 + 每条认领的数字 + 发布顺序建议

## 8 · 纪律

- 不许编体验。没上手就写"官方说法"，不写"我用了两天"
- 不许把传闻写成定论；传闻必须带「传闻 / 未确认」
- 不许为凑数加水页；信息点只有三条就只做三张
- 每套 3 张，上限 5 张；超了拆两组，或把最弱的信息点降级进结论条
- **六套首图重复 = 直接不算完成**，宁可换页型重排
