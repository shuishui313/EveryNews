# 单条深挖

输入是一个链接或一个话题，输出是**一条**能发的稿子。和 `daily-6` 的分工：那边是每天 6 条广度，这边是单点深度。

## 0 · 先定问题

拿到链接/话题，先用一句话写下「这条到底在回答什么」，例：

> 灵光 2.0 把 AI 从任务执行变成事务管理，代价是权限。

写不出来就先去查，别先动笔。

## 1 · 多源检索（至少四路，缺一路不算查过）

| 路 | 找什么 | 为什么 |
|---|---|---|
| 官方原文 | 公告 / 博客 / 发布会实录 / 产品页 | 唯一可引用的口径 |
| 二手报道 ≥2 家 | 有没有互相矛盾的数字 | 交叉验证 |
| 社媒讨论 | X（经聚合镜像，见下）、Reddit、Hacker News、小红书、微博、知乎 | 真实争议点在哪 |
| 反方 / 质疑 | 有没有人指出漏洞、利益关系、样本问题 | 决定这条稿子的落点 |

**X 侧怎么查**：`x.com` 时间线与搜索需要登录态，直接抓是空壳。走 `web_search` 搜 `site:x.com <关键词>`，命中通常是原帖的转述镜像（doomers.ai 记录传播量，postcutoff.com 存原文＋日期）；趋势看 `trends24.in` 这类公开趋势页，打不开就退化为 HN / Reddit 热帖。**X 只说明"什么在传"，不当事实源**：引用必须落到原帖链接，拿不到原帖就不写"某某发推说"。

检索优先级：官方 > 一手实测 > 主流媒体 > 社媒。社媒只用来看"大家在吵什么"，不当事实源。

**关键动作**：把原文完整读一遍，专门找"它没说什么"。多数稿子的价值在缺口里，不在通稿里。

## 2 · 沉淀两张表

### 事实底稿

```
核心结论（一句话）
时间 / 主体 / 事件
可核对数字（含单位、口径、年份）
官方引语（原话，可直接引用）
未确认项（官方没说的）
风险提示（原文自己承认的问题）
```

### 讨论地图

```
阵营 A：观点 + 代表性说法
阵营 B：观点 + 代表性说法
真正的分歧点：___
大家没在讨论但重要的：___
```

写完这两张表再动笔。表不齐就地补检索。

## 3 · 决定形态

- 有反转、数字多、要拆解 → **1 条主推 + 3 张卡**（本体 / 数字 / 判断），Threads 用串 3 条
- 一句判断就能说清 → **1 条 + 1 张卡**，Threads 单条
- 纯体验/工具 → **1 条 + 3 张卡**（体验 / 边界 / 异议）

## 4 · 写文案

结构固定：

```
X 主帖（一条，开头或结尾一句人味，中间全是硬信息）
Threads（一条，标签放末尾）
原文：<完整 URL>
```

两个平台每条都**结尾带 `原文：<完整 URL>`**，完整链接，不用短链。X 不拆串，也不再补评论。

四条纪律：

1. 数字逐字对原文，旧数字标年份
2. 没实测就说"官方说法"，不装用过
3. 判断只落在账号能长期站住的位置（技术事实、产品边界、授权与成本），不引申到公司与国家层面
4. 一条稿子只挂**一个主来源**（官方原文优先）；抄了多家时其余链接放事实底稿，不堆进推文

## 5 · 出卡

见 `cards/PROMPT.md`。1 张就 `cover` 或 `statement`；3 张常规组合：本体 / 一个压得住全场的数字 / 一句判断。

```bash
cd cards && ./make.sh <slug> && cd ..
for i in 1 2 3; do cp "cards/out/<slug>/slide-0$i.png" "assets/<新闻名>-0$i.png"; done
```

出图后逐张看：有没有大块空白、标题数字是否与正文重复、结论条是否只有一句。

## 6 · 交付

- 文案：`发布包/单条-<slug>-YYYYMMDD.md`
- 配图：`assets/<新闻名>-01.png`（或 01–03）
- 回复里给：核心结论一句 + 三处最容易被转发的点 + 一句风险提示（哪句话最容易被挑刺，以及怎么答）
