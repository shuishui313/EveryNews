讲① 40 個 Agent，同一個專案

影片
Android Developers · Android Dev Summit 2026 keynote · 1:01:55 · https://www.youtube.com/watch?v=8Lmv7LGgL4E
判據
能照做（BYOA 和 CLI 插件都已穩定，裝完就能接）· 有邊界（端側接口還是 alpha，Lightbuild 仍在測試）· 時效（2026-10-28 發佈，工具鏈接口三個月內不會大改）
局面
中文側都在報 XREAL 眼鏡和 Android 18 的圖形，這條 keynote 給開發者的東西反而沒什麼人講，就是把自己的工程環境開放給外面的 Agent

先把一件事交给外面的 Agent，看它会不会把编译弄坏。

这条一小时的 keynote 讲的就是怎么交、交到哪一步。看完你能自己判断项目里哪几件事可以放手，哪几件一放手就要回滚。

Android Studio Rabbit 2 这次开了口子。它在内置市场里挂 Agent，官方点名的有 Anthropic 的 Claude、OpenAI 的 Codex，还有自家的 Antigravity，加起来四十多个，能同时装、同时跑。协议用的是开放的 Agent Client Protocol，谁都能接。

进来的 Agent 权限不小。它能读项目结构、解析符号、自己开模拟器、翻 Logcat，一个新人坐在你电脑前能做的也就这些，差别是它不问你问题。01:59 那段演示的顺序很具体，先让它自己找崩溃，再让它改，改完自己跑一遍。

脏活里最先能交出去的是三件。

**1 · 找漏**

LeakCanary 内建进 CLI 和 Profiler，堆转储挪到电脑上分析，不再拖慢手机。官方拿 Claude Opus 5.5 做了对照，找内存泄漏快近两倍，token 少用约四分之一。

**2 · 看界面**

CLI 能在终端里渲染 Compose 预览，不用起模拟器就能看改动。内部测下来，Agent 做界面任务快 77%，token 最多省三倍。

**3 · 上架前**

三十多个 Android Skills 把最新文档喂给它，覆盖 Play 上架政策预检、权限安全、折叠屏和 Googlebook 笔记本的响应式布局。模型的训练数据里不会有上个月的 API。

提交前还有一道 Change Review，把待提交的改动跑一遍，出 bug 报告时连改哪一行都写出来。这一段拿给 reviewer 看，能省几轮来回。

卡人的地方在后头。BYOA 和 CLI 插件是稳定的，Android Bench 2.0 已经能按功能完成度、耗时和成本给模型打分，Lightbuild 还在测试，构建配置写成 YAML，人和 Agent 读同一份，接生产流水线之前得等它转正。

Android Skills 只覆盖 Google 自己的流程。你们公司内部的命名规范、分支规矩、灰度策略，它一概不知道，那份说明文件得你自己写，写完还得让它每轮都读。

装好之后半小时能跑起来，官方文档里列了支持的 Agent 清单，装之前对一眼。第一个坑是权限一次开到最松，它会直接改文件，改完你翻记录才知道动了哪几个。先让它出方案，你看一遍再松手。

这一轮 Google 卖的是接口，模型换掉，接进来的工程环境不用重建。

最值得看 31:10 那一段，Android MCP 和 CLI 怎麼接

讲② 模型只能拼你給的組件

影片
Android Developers · Android Dev Summit 2026 keynote · 1:01:55 · https://www.youtube.com/watch?v=8Lmv7LGgL4E
判據
能照做（組件目錄就是普通 Compose 代碼，聲明完就能跑）· 有邊界（A2UI 還是 alpha，只能拼已經聲明過的組件）· 時效（協議層三個月不會變，2026-10-28）
局面
中文側把這場峰會讀成硬件發佈會，A2UI 這類讓界面變成動態產物的東西反而沒人細說

让模型拼界面，但只准用你给的零件。

这是 Android Dev Summit 上 A2UI 做的事。看完你能看懂一份组件目录该怎么声明，也知道哪类界面不该走这条路。

界面从 XML 搬到 Compose 讲了好几年，这次 keynote 把它说成既定方向，后面的 A2UI 才接得上。模型的输出是一段 JSON，说这里要一张卡片、两行字、一个按钮，App 把它映射成原生 Compose 渲染，全程不执行模型写下的代码。23:28 那段的演示就是照这个顺序来的。

能拼出什么，取决于目录里写了什么。

组件目录写清楚有哪些组件、每个组件吃哪些属性、能调哪些本地函数。模型拿到的是这张菜单，从里面挑，碰不到别的。菜单窄，拼出来的东西规整；把整个 Material 组件库一次塞进去，它能拼的花样多，怪东西也多。

要动手调的是三块。

**1 · 拼界面**

A2UI 的 Compose 渲染器这个月是 alpha。它管把 JSON 翻译成原生组件，管不了业务逻辑，按钮点下去做什么还是你写。

**2 · 交功能**

AppFunctions 进了 beta，做的是统一工具调用层，把 App 的功能分享给本地或系统级 Agent。用户说一句把这张发票存进记账软件，走的就是这层。

**3 · 端侧跑**

Gemini Nano 4 的 Agentic API 还是 alpha，挂在 ML Kit 的生成式 AI 模块里，替你管函数调用、聊天历史、编排循环和安全过滤器。联网不稳、不想把数据送出去，这一层是唯一选择。

安全这块官方没给硬保证。有位开发者在 Medium 上写了测试，他造了六个恶意 payload 打官方 schema，五个通过。目录声明得越宽，断言之外留下的空间越大，剩下的靠你自己收。

上手要一个 Compose 项目和一个能开 alpha 的渠道，一下午能声明完一个目录。第一个坑是照着 Material 组件库抄，抄完等于把整个界面库交出去。先从三五个组件开始。

界面结构固定的时候不该用它。列表、表单、详情页，喂给模型只会更慢更贵，token 花在拼装上看不见回报。适合的是每次内容都不一样的界面，行程、报价、体检报告这一类。

A2UI 的渲染器还是 alpha，AppFunctions 到了 beta，中间差一个版本。这个差距决定了现在能做演示，还做不了生意。

最值得看 23:28 那一段，A2UI 從協議到組件目錄
