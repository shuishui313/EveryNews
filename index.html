三分之二少招人，裁掉的只有两家

Anthropic 把 58 家企业客户的 66 次访谈摊开，最扎眼的一栏是招聘。三分之二的公司说因为 AI 少招了人，真正砍掉岗位的只有两家。自上而下推 AI 的老板容易撞上另一堵墙，员工担心技术盯着自己干活，抵制一上来，自动化要么被闲置，要么靠人反复兜底撑着。报告把这类产物叫作脆弱的自动化，看着上线了，其实没人敢把它接进关键流程。

ESSAY 01 635 漢字 · 深度拆解

合并键交给代理之前，先让它只看不动手

原文https://claude.com/resources/articles/introducing-claude-ship
判据读完能照做，写清适用边界，三个月内仍有参考价值

Claude Ship 把一次 Pull Request 从提交到合并拆成三段，读完你会拿到一把尺子，用来判断自己的仓库现在够不够格把合并键交出去。Anthropic 在 11 月 23 日放出这套流程，Code Review 已经正式可用，PR Steward 和 Claude Approvals 还在测试。

审查这一段先要证明自己看得准。Code Review 收集问题后会做一轮对抗性验证，再分类发到 PR 上，每个仓库可以挑 Quick、Standard 或 Deep。官方给的自述数字是 Claude Code 团队从六月到九月合并的 PR 多了一倍以上，回滚的比例降了四成多。这组数没有第三方复核，读的时候按公司自述对待。

修绿那段交给了 PR Steward。检查挂了、分支冲突、同事留了意见，它都会动手改，每次 push 后留一条评论说明改了什么、怎么撤销，你还可以在评论里打上 @claude stop 让它停手。它明说不批准也不合并，这条自我限制是它能先上线的理由。

批准权落在仓库的一份文件里。Claude Approvals 读默认分支上的策略，官方把它比作更聪明的 CODEOWNERS，例行改动可以按策略直接放行，需要人签字的一律往上送。代理再聪明也只是在策略框架里跑，仓库原本的分支保护和必需检查仍是放行的硬条件。官方建议大多数团队先用只看不动的观察模式，跑顺了再让分支保护去要求它的绿灯。

算钱的时候有两笔账。整套按 token 计费，管理员能给 Code Review 和 PR Steward 设月度上限，策略里的 classifier 也按 token 走，观察模式照样会触发计费的审查。零数据留存、HIPAA 配置、客户自管密钥的组织被排除在外，Enterprise 组织可以领至少一万美元额度，2027 年 1 月 15 日截止，领了要在 30 天内用完。

这套流程适合改动密集又愿意写策略的团队。仓库就几个人，PR 一天不到几条，配策略盯账单的工夫比省下的审查时间还多，先按原来的节奏走更划算。

官方那句合并结果取决于开发者权限和仓库分支规则，其实已经交底。代理没有新增任何权限，它把原本分散在几个审查环节的人手压成一次调用，能这么做的团队前提是仓库保护规则本来就密。规则松的仓库先接这套流程，只会把草率合并做得更快。

EDITOR'S NOTE · 最值得看

官方上线步骤里把 approval policy 放在观察模式跑一段再要求绿灯的那几行，顺序写得很清楚。

ESSAY 02 637 漢字 · 深度拆解

岗位没消失，招人先停了，读懂那 58 家企业的账

原文https://www.anthropic.com/research/working-with-ai
判据读完能区分岗位消失与停止招人，看清样本边界

这篇讲 Anthropic 那份客户访谈报告里最容易被转述错的一栏，读完你能拿走一个区分，岗位消失和停止招人是两回事。报告在 11 月 23 日发布，基于 58 家企业客户的 66 次访谈，作者来自 Anthropic 自己。

减少招人为什么先发生。报告里产出增益有一半来自加速原有工作，另一半来自新产品和服务质量提升，AI 写的软件里八成接手原本人工的活，两成替掉外购软件。省下来的首先是工时，工时变化最先写在招聘计划上，离裁员决策还有一段距离。

自上而下推 AI 的代价另有账本。老板压着要用，员工担心被监控，也担心被推去干不熟的活，抵制一上来，自动化要么被闲置，要么长期靠人兜底。报告里律所的例子很具体，运营负责人让员工做个查利益冲突的工具，技术并不难，卡点在接不接受人被它检查。

招聘冻结比裁员更容易拍板，这是从材料里推出来的判断。冻结不需要走岗位撤销那套流程，也不用回答谁被替掉，财务上先把新增人头拿掉，效果立刻见效，所以两份数字才会差得这么远。报告本身没有把这条写成结论，它是把招聘和岗位拆成两栏之后自然成立的。

样本边界得说清。58 家、66 次访谈集中在法律、制造、金融、医疗和物流等行业，作者明说这不是随机抽样，不能当全美企业的比例来用。AI 导致的裁员在这个样本里只出现两家，同样只是这批客户里的观察，换一批客户未必需同样的数。

要不要把这条写进自己的报表，取决于你手上是工时数据还是岗位数据。多数公司先动的是外包和空缺，正式编制的文件来不及改，看岗位表会以为什么都没发生，看招聘漏斗才看得到那道刹车。这两种口径差着一个季度，用错了一整年的规划都跟着偏。

转述最容易漏掉的是那堵墙。工具装上不等于流程改完，员工把不信任留在交接处，自动化就停在半路，这份报告把这条写成脆弱的自动化，值得记下来。

EDITOR'S NOTE · 最值得看

报告摘要里 hiring less 与 two had seen AI wipe out a position 的那两句对照，把两栏数字并排放着。
