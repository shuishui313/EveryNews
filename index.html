01 arXiv 2611.34813 COVER STORY · 本期頭條

写程序比生成视频更会看图

卡内基梅隆的研究把同一批视觉推理题同时交给写程序的代理和生成视频的模型，在 VBVR-Pro-Bench 的五百道题上，Codex 配 gpt-6-astra 拿到 0.923，比最强的视频模型高出 0.22 以上。做法是让代理看同一张首帧和提示词，写一段程序把答案渲染成视频，再交给同一个未经修改的规则评估器打分，代理拿不到标准答案和生成模型。开源模型里最好的 GLM-5 只有 0.572，低于经过强化学习训练的视频模型。结论有明确边界，只对那些能从首帧和提示算出来的题目成立，规则评估器也天然偏向符号化的确定答案。

02 arXiv 2611.34051

线性注意力状态爆炸后，对称擦除把它稳住

MemTensor 的论文找出 Gated DeltaNet-2 在长上下文训练里失败的原因，擦除状态时读取方向与修改方向不对称，形成非正规算子，方向性增益跨 token 累积，就算没有新写入，状态也会指数级长大。修法是改成对称擦除，让状态传播不再扩张，再用衰减调节的残差写入保住表达能力，分块并行计算也保留了。研究者在约十六亿参数的模型上验证，循环设置下 128K 的 RULER 平均分比 GDN-2 高 6.80，混合设置下九个下游任务平均高 0.62。摘要给的状态上界是 O(T)，提交者评论写成 O(√T)，以正文为准。实验只做到十六亿参数，放大到更大模型是否照样稳定还没有答案。

发布论文 11 月 25 日，11 月 27 日提交，当日第 1 热门，128 赞
病因擦除时读取与修改方向不对称，形成非正规算子，方向增益跨 token 累积，状态指数增长

03 欧洲央行博客

四成四每周用 AI，工作量反而变多

欧洲央行十一月二十七日公布的消费者预期调查显示，2026 年八月欧元区有四成四的就业消费者每周至少用一次 AI，约一成八每天用，五月这个比例还超过五成。用它的人里，约五成六说 AI 增加了完成的工作量，四成七说产出质量提高，最常被提到的功能是查找和处理信息。受访者对五年后的预期也从一年前的三成四升到四成六。这份调查用的是欧洲央行自己的 CES 口径，和美国盖洛普的问题与样本都不同，跨区比较只能看趋势。同一篇博客还给了一组对照，从 2021 年到 2027 年底美国企业投资预计增长约四成，欧元区只有约一成二。

04 NVIDIA

开了三套数据，文档解析快了六倍

NVIDIA 把文档解析模型 Nemotron 3.5 Parse 的三套训练数据开了出来，合成图表九百九十八万条，合成表格一百万条，多语言 OCR 七百九十万条，每套都附了图像、标注和训练格式。模型改成按页面形状动态输入，注意力分组数砍到八以压住缓存内存，再配一个最多向前猜三十二个 token 的草稿模型。单卡 H200 跑同一组两千零七十八页，上一代每秒不到三页，新一代不加草稿模型是十三点四八页，加上之后到二十点四四页。微调配方也放出来了，合成牙科表单上基础模型的 pass@1 是零，微调后到九成五八。对照题目出自同一个生成器，换到真实扫描件还要自己再验一遍。

05 ggml-org

本地推理跑分，原始档也一起开了

ggml 团队在 Hugging Face 上线了 llama.cpp 的 AMD 跑分仪表板，能选 Radeon 8060S 和 AI Pro R9700S 两张卡，按模型、量化格式和版本交叉比对。仪表板把 PP512 与 TG128 分开报，前者量五百一十二个输入 token 的处理速度，后者量生成一百二十八个 token 的速度，都从零上下文起步。每周自动跑的结果连同 Flash Attention 开关的十次重复放进公开数据桶，别人可以拿 jsonl 重画图或和本机结果对账。模型清单有 Inkling 2 Mini、Qwen、Gemma、gpt-oss 和 LFM，四比特到 BF16 都能选。

ESSAY 01 770 漢字 · 深度拆解

四個代理怎麼學會互相傳消息

原文https://huggingface.co/blog/training-swarms
判據讀完能照做，寫清適用邊界，三個月內仍有參考價值

Hugging Face 十一月二十六日發的多代理訓練筆記，回答一個容易被跑分掩蓋的問題，幾個代理互相傳訊息到底有沒有幫上忙，還是只是把同一筆算力花了更多倍。讀完你能拿走一把尺子，判斷別人展示的多代理提升是不是靠同預算換來的。

任務裡四名代理各自拿到一個一到九十九的整數，只知道自己的數字和隊友名字，要靠傳訊息把四個數排序，重複的數字也要保留。四個代理共用同一個 Qwen3-0.6B 策略，不是各訓練一個模型。成功條件很寬，只要有一個代理交出完整正確的列表就算整隊贏。

通信工具只有發訊息、讀郵箱、查未讀三個動作。設計藏在獎勵裡。隊伍總預算是四倍的八千一百九十二個工作 token 加一千零二十四個最終答案 token，合計三萬六千八百六十四。獎勵等於成功乘以一個折扣，用掉的 token 越多折扣越大，發再多訊息也不加分。

訓練採集中訓練分散執行，訓練時看得到全隊資訊，上線後每名代理只靠自己的觀測。每次更新收集三十二道題，每題八次獨立嘗試，同隊四人共享一個隊伍優勢，哪怕其中一人自己交的答案不對。loss 先在隊內平均再跨隊平均，避免長對話拿到更高權重。

效果曲線很直接。前五次更新成功率百分之六點五六，到第七十一至七十五次更新時升至百分之八十二點三四，每隊消耗的 token 由一萬二千八百多降到八千多，節省約三成七。每隊廣播次數從二點三八升到五點七三，訊息變多，總 token 反而變少。checkpoint 75 在留出集上解對三十二題裡的二十六題。

作者接著算了一筆帳。沒訓練過的隊伍就算跑八次挑最好的一次，成功率也只有百分之三十七點五，約吃掉十萬三千個 token。訓練過的隊伍一次就有百分之八十二點三，只用約八千個。把通信練出來比反覆重試便宜一個數量級。這筆對照用的是訓練題不是留出集，前幾次更新也摻了一點訓練，數字是估計。

邊界得說清。作者承認這道題不適合驗證同預算下的通信收益，單個代理拿不到全部數字，根本解不了，比的是共享策略能不能學會通信以及代價。token 效率沒有留出集數字，原始實驗用一張 H200 訓練加七張跑 vLLM，入門版也要兩張 H200 跑約五小時，花約五十美元。能搬走的是做法，先設計一個單代理鑽不了空子的任務，把 token 算進獎勵，再用同預算比較訓練前後。

EDITOR'S NOTE · 最值得看

原文從百分之六點五六升到百分之八十二點三四的那張更新曲線，連同每隊 token 從一萬二千多降到八千多的對照，把學會通信的收益一次給全。

ESSAY 02 725 漢字 · 深度拆解

Trainium3 上把十秒影片壓到二十二秒

原文https://huggingface.co/blog/video-trainium3
判據讀完能照做，寫清適用邊界，三個月內仍有參考價值

Hugging Face 十一月二十七日的工程筆記，講的是同一個影片生成模型換到 AWS Trainium3 之後，怎樣從慢到不能用變成接近即時。讀完你能拿走一套排查順序，遇到新硬件上的推理任務，知道時間究竟花在哪裡。

起點很樸素。LTX-2.5 是個能同時出畫面和聲音的模型，第一次在四個 NeuronCore 上跑，生成十秒 960×544 的影片要五分二十秒，其中裝置上計算只佔四十五秒，剩下全耗在主機側。時間花在把資料搬來搬去和沒串好的流程上，核心自身的計算其實很快。

先把模型放下來是第一步。Transformer 塞不進單一核心，diffusers 也沒有對應的張量並行方案，團隊自己打補丁，按四路切權重、八路切影片 token，最後用三十二個核心，等於半台 trn3.48xlarge。注意力頭只有三十二個，張量並行到四就得停。文本編碼器不能和 transformer 住同一核心，留在 CPU，潛空間上採樣和解碼也一樣。

真正的時間黑洞一個個被挖出來。提示詞本來被補齊到一千零二十四個 token，CPU 編碼器在對無效填充做白工，只編真實 token 後從三點四秒降到一點四秒。rank 零的 CPU 執行緒被另外三十一個 rank 搶走，手動釘住後從七點四秒降到三點三秒。參數塞進不超過 1 GiB 的緩衝區，避開記憶體配置器的浪費。影片解碼本來在 CPU 上要三百五十七秒，搬進核心並按幀切分後只要一點六秒。

結果是十秒 2048×1024 的影片用二十二到二十三秒生成，比最初快十四倍，像素數還多了約四倍，花的是六十四個核心裡的三十二個。同一個模型走 LTX 在線 API 出十秒 1080p 要二十三點七秒，兩邊幾乎打平。作者找不到可靠的 CUDA 數字，LTX 自報的四張 B200 跑六點八秒沒有測量細節，所以沒做直接對比。

邊界寫得很實在。單鏡頭最長二十秒，主體一致性靠前一鏡頭的最後二十五幀當條件，光靠提示詞會換人，山羊的角四個 take 裡有三個畫錯，通常每個鏡頭做四次再挑。聲音按鏡頭單獨生成，不會自然跨鏡頭連續。拿來做機器人訓練更不能直接用，真實片段只給一秒時模型判斷不了速度，也壓不過原影片裡已經確定的物理狀態，要拿自己的影格和動作微調檢查點。

能搬走的是排查次序，先量出時間花在主機還是裝置，再動並行切分，最後才碰精度與快取這類細節，每一步都有前后數字對得上才算數。
